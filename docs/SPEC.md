# Wand Playground — 仕様書

## 1. 概要
Noitaの「杖を組む→試射する→組み直す」楽しさをブラウザだけで体験できる、非公式・無料の2D杖サンドボックス。ゲーム本編、ピクセル物理、全呪文の完全再現は対象外。**操作の軽快さとビルドによる派手な変化**を優先する。Noitaの原作素材やソースコードは無断同梱しない。

## 2. 体験と対象ユーザー
- Noitaを遊んだことがあり、杖の組み合わせを気軽に試したい人。
- 起動後すぐに杖を編集・試射できる。アカウント・サーバー・有料API不要。
- PCファースト（マウス・キーボード）。スマホでは編集・タップ試射可能なレスポンシブUIを提供。
- 面白い杖はブラウザに保存し、URLで他人に共有できる。

## 3. 画面・基本操作
PC: [試射場（主領域）] + [呪文一覧・検索（右）] + [杖編集・性能調整（下）]。スマホ: 試射場/編集のタブ切替。
- 呪文一覧: 名前・カテゴリで絞り込み、クリック/ドラッグでスロットに追加。
- 杖: スロットをドラッグで並べ替え、複製・削除、空きスロット追加、Undo/Redo。
- 杖性能: 容量、マナ最大値、マナ回復/秒、詠唱遅延、リチャージ、拡散、シャッフルの有無。
- 試射: マウス位置へ発射、長押し連射。スマホはタップ照準 + 射撃ボタン。停止/リセットボタンを常設。
- エディタの変更は次の詠唱から即反映。実行中の弾は変更前の挙動を維持。
- 試射場には床、壁、HPを持つダミー、ダメージ数字とDPSを表示。
- ゲーム的なプリセットを数種類用意し、初回起動でも1クリックで射撃できる。

## 4. MVPに含める機能
1. React + TypeScript + Vite の静的SPA、PixiJSによる描画。
2. 杖編集・性能調整・呪文検索・ドラッグ操作・プリセット。
3. 呪文のデータ駆動定義とシンプルな詠唱エンジン。
4. 基本弾の移動・衝突・ダメージ、複数弾、弾速/拡散/ダメージ修飾、簡易爆発とパーティクル。
5. スパークボルト相当の単発弾、バウンド弾、複数詠唱（二重/三重）、弾速増加、ダメージ増加、拡散、爆発、チェーンソー風近接弾など、**独自描画による最初の約10〜15種類**。
6. 消費マナ、回復、詠唱遅延、リチャージ、連射、マナ不足時挙動。
7. ダミーのHP/ダメージ数字/直近5秒のDPS、リセット。
8. IndexedDBまたはlocalStorageによるビルド保存（初期はlocalStorageでも可）・インポート/エクスポート・URL共有。
9. GitHub Pages自動デプロイ、基本テスト、使用方法と非公式表記。

## 5. Phase 2（MVP以降）
- トリガー・タイマー・修飾呪文の連結、詠唱順序、呪文ラッピング、シャッフル挙動の精緻化。
- 追尾、貫通、ビーム、掘削弾、電撃、連鎖爆発などへ拡充（目標20〜30種）。
- 詠唱デバッガー: 評価順、発射された弾、マナ・遅延の変化をステップ表示。
- 敵/障害物配置、スロー再生、弾数制限の表示、性能設定。

## 6. Phase 3
- 簡易破壊可能地形、2ビルド比較、録画/WebM保存、GIFは必要に応じ追加。
- 正確なNoita挙動を目指す互換モードは独立した後続課題。原作と違う挙動を明示。

## 7. 詠唱モデル・優先順位
- `Wand` = `stats` + 順序つき `slots: SpellInstance[]`。呪文はID・種別・マナコスト・パラメータを持つデータ定義。
- `SpellEngine` は杖状態と入力から、決定的な `CastEvent[]`（ProjectileSpawn, Effect, ManaUse, Delay 等）を生成する。視覚表現は含めない。
- `SimulationEngine` が固定タイムステップでイベント、弾道、衝突、ダメージ、寿命を処理。
- `Renderer` がシミュレーション結果をPixiJSで描画。ゲームロジックと表示を分離。
- MVPの詠唱規則は簡略モデルとして文書化し、原作一致は保証しない。複数詠唱や修飾の合成について単体テストを用意。シャッフルは乱数seed固定で再現可能にする。

## 8. データ例（設計イメージ）
```ts
type Wand = {
  id: string; name: string;
  stats: { capacity: number; maxMana: number; manaRegenPerSec: number;
    castDelayMs: number; rechargeMs: number; spreadDeg: number; shuffle: boolean };
  slots: { instanceId: string; spellId: string }[];
};
type SpellDefinition = {
  id: string; name: string;
  kind: 'projectile' | 'modifier' | 'multicast' | 'utility';
  manaCost: number; params: Record<string, number | boolean>;
};
```
保存データには`schemaVersion`を含め、未知のspellIdや破損データでクラッシュしないこと。

## 9. 性能・安全性
- 目標: 一般的なデスクトップで60fps、モバイルで30fpsを目指す（保証ではない）。
- 弾、粒子、爆発連鎖に上限設定。上限到達時は可視化して描画負荷を下げる。
- リサイズ/DPR対応。ページ非表示時にシミュレーション停止。メモリリークを避ける。
- URL共有は長さ上限・スキーマ検証・サイズ制限を設け、任意コードの実行を許可しない。
- 原則オフライン処理。外部APIとアカウントを要しない。

## 10. 技術スタック
- React / TypeScript / Vite
- PixiJS、Zustand（UI状態）
- Vitest（詠唱・シミュレーションの単体テスト）、Playwright（主要操作のE2E、必要に応じ）
- GitHub Actions → GitHub Pages。サーバーなし、ランニングコストゼロを目標。

## 11. 受け入れ条件（MVP完了）
- 初期プリセットを選び、30秒以内に初回試射できる。
- 呪文の追加・移動・削除が即時反映される。
- 単発弾/複数詠唱/修飾/爆発が視覚的に区別できる。
- マナ消費と詠唱遅延が挙動に反映され、長押し連射可能。
- ダミーへの命中でHP減少・DPS表示、リセットで初期状態に戻る。
- ビルドを保存・再読み込み・URL共有でき、異常な共有データでもクラッシュしない。
- CIでビルド・テストが成功し、GitHub Pagesから利用できる。

## 12. 非目標と権利
- Noita本編、ワールド生成、液体・粉末・炎の完全なピクセル物理は再現しない。
- 原作の画像、音声、プログラムを許諾なくコピーしない。オリジナルのアイコン/効果音/描画を使用。
- 説明文とアプリ内に「非公式ファン制作、原作との挙動差あり」を明示し、権利者のガイドラインを確認する。

## 13. Issueの進め方
Phase 1を縦に動く小さな実装で完了させる。最初にアプリが起動して弾が出る状態を作り、編集、詠唱、ダメージ、保存の順で進める。各Issueはチェックリストを完了条件とし、機能追加時はテストとデモ用プリセットを更新する。
